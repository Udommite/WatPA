# WatAssets — ระบบทะเบียนทรัพย์สินวัด

Working Phase 1 foundation: Thai React application, real PostgreSQL persistence, authentication, tenant authorization, editable assets, configurable categories and locations, multiple private photographs, primary photo selection, PDF evidence, movement/edit history, encrypted offline queue, conflict resolution, and basic physical inventory.

**This is a development pilot, not a production-certified or government-approved release.** PDF/XLSX registers are available as clearly marked draft review templates, with source-matched column groups, Thai fonts, Buddhist Era dates and repeated headers. They are not approved official forms. Excel/CSV import supports mapping, preview, validation and atomic local queuing; a separate photo catalog PDF is also available. See the honest [delivery matrix](docs/acceptance.md) and [architecture](docs/architecture.md).

## Run on Windows

Requires Node.js 22 or newer (tested with Node 24).

```powershell
cd C:\Users\Putter\WatAssets
npm ci
npm run setup:local
npm run seed
npm run build
npm start
```

Open **http://127.0.0.1:3100**. The local setup creates a random administrator password in `LOCAL-ACCESS.txt` and an ignored `.env`. Setup does not overwrite an existing `.env`. The seed is idempotent and creates five clearly marked DEMO assets. Do not share `.env`, `LOCAL-ACCESS.txt`, or `data/`.

For development: `npm run dev`, then open http://127.0.0.1:5173. PWA caching is generated by `npm run build`; use the built app on port 3100 for offline testing. The backend must remain running for other users to synchronize.

## Try the workflow

1. Sign in with the generated administrator account. Wait for the five sample assets.
2. Add a category or a nested location. They persist locally immediately and synchronize automatically.
3. Add an asset, keeping an unknown value blank. Attach photos in the form, or open its details to add photos/captions and PDF evidence. Choose the primary image in the gallery.
4. Under users, create a separate staff/viewer account with a unique password. Use a second browser profile to verify collaboration.
5. Install the PWA where supported. After the first online sign-in and successful caching, disconnect, register an asset, close/reopen, and unlock using the same password within the eight-hour lease.
6. Reconnect. Records upload before media; pending indicators clear only after acknowledgment. Concurrent stale edits appear in a field-choice conflict dialog.
7. Change an asset location and enter a movement reason. Open its history to inspect the retained versions and transfer event.

## Offline design

Dexie stores AES-GCM encrypted data and a durable operation queue. The password-derived encryption key remains in memory. Each operation has a client UUID and a base revision. The central server transaction writes the record, relational projection, audit, movement event, and operation receipt atomically. Replays cannot duplicate a record. Revision conflicts preserve both versions until resolved. Exponential backoff retries network failures; a snapshot pulls other users' changes after upload. No business data or authentication token is stored in localStorage.

Offline edits become visible to other users **only after successful sync**. The app synchronizes while open/on reconnect; closed-browser background sync is not implemented. Logging out preserves encrypted pending records. Revocations take effect on the next server contact, with an eight-hour offline lease ceiling in the normal application flow.

## Tests

```powershell
npm test
npm run build
```

Tests launch a real disk-backed PostgreSQL engine and HTTP server, verify sessions/roles/tenant isolation, custom taxonomies, registration, replay, revision conflicts, secure media, transfer/audit history, and revocation. IndexedDB tests use `fake-indexeddb` to verify encrypted persistence, wrong-password rejection, lock/reopen, and reconnect idempotency. These are not a substitute for real Android camera, PWA restart, and multi-device acceptance testing.

## Deployment and backup

See [deployment.md](docs/deployment.md). Local evaluation is preconfigured. No hosted deployment, Supabase project, cloud storage account, or public inventory was created. `DATABASE_URL` allows external PostgreSQL without replacing the API. The server binds to loopback for reverse-proxy deployment.
